Veeam Backup & Replication v13 · VMware vSphere

AutoDeploy Proxies

Deploys, registers and replaces Veeam Infrastructure Appliance (VIA) 13.1 backup proxies in bulk, from one CSV. What takes an admin about 45 minutes of clicking per proxy becomes one unattended run per VBR server.

It uses only documented interfaces: the official appliance ISO with its unattended-install answer file, VMware PowerCLI and the Veeam REST API. It works fully offline (dark sites) and keeps no clear-text secrets on disk.

How a run works

1 · PlanFleet PlannerWeb page: naming pattern, IP range, cluster, datastore, tags. Exports the CSV and the commands.
2 · CheckValidate + What-ifPlacement, names, DNS, tags, VM groups, secrets and free IPs, checked before anything is built.
3 · DeployUnattended installA per-node ISO, a UEFI / Secure Boot VM, install and first-boot configuration. About 25 minutes.
4 · RegisterInto the VBRCertificate trust, proxy role, task slots and transport mode, done over REST. A report per row.

What it can do

Deploy at scale

  • Any number of proxies from one CSV, one VBR per run
  • Up to 16 appliances at the same time; several VBRs side by side
  • VM sizing, a data disk, logs on disk 2, a second NIC for a backup network
  • Roles: VMware proxy, gateway server for Data Domain / StoreOnce
  • Also deploys the Veeam Software Appliance (backup server, Enterprise Manager)

Replace without losing jobs

  • Records every job and repository that uses the proxy
  • Finds the old VM by its IP, even after a rename to a new naming standard
  • Shuts the old VM down and renames it <name>_ToBeDeleted
  • Deploys the new appliance and puts it back into the same jobs
  • Jobs keep running on automatic proxy selection in the meantime

Fits the customer's standards

  • Separate VM name and host name patterns (e.g. dc_org_site-cluster01)
  • Search domain; DNS A and PTR records created in AD DNS
  • vSphere tags on every VM (team, owner, contact …)
  • DRS VM/Host groups per site
  • Loads the real vSphere inventory, so typos show up in the planner

Safe by default

  • Validate and What-if before every real run
  • Skips rows whose name already exists; refuses IP conflicts
  • Rollback removes only what the run itself created
  • Passwords, MFA seeds and credentials encrypted at rest (AES-256)
  • VBR accounts with MFA (TOTP) supported

Deployment server

  • Ready-made Rocky Linux VM that runs the whole toolkit from a browser
  • Reached through an SSH tunnel, or HTTPS with client certificates
  • Built from a self-installing ISO; on Windows even without xorriso or WSL
  • Everything on board: no internet needed at install or run time

No vCenter access? Still works

  • ISO-only mode: one ISO per node, one ISO with a boot menu, or one that asks at install time
  • A VM build sheet for whoever creates the VMs
  • Registration afterwards, with VBR access only

Assumptions (estimates, adjust to the customer):
  • By hand, per proxy: create the VM, run the appliance installer and initial configuration, add it to the VBR, set the proxy role, DNS, tags and group: about 45 minutes.
  • Replacing by hand also means writing down and re-doing the job and repository assignments and handling the old VM: about 70 minutes per proxy.
  • With the toolkit, per VBR: plan in the planner, Validate, What-if, start, check the report. About 1.5 hours for a deploy run and 1 hour for a replace run. The runs themselves are unattended.
  • Appliance run time: about 25–30 minutes to deploy and about 35 minutes to replace. A replace runs one proxy at a time per VBR, so job edits can't overlap.
  • Not counted: fewer typos and failed installs, and a consistent result on every proxy.
